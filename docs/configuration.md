# Configuration

All configuration comes from the environment. `python-decouple` reads `.env`,
and real environment variables take precedence over it — which is how CI and
container overrides work.

`.env` is generated by `scripts/bootstrap.sh`. You should not need to edit it to
get started.

---

## Required

These have no default. Django will refuse to start without them.

| Variable | Description |
|---|---|
| `DJANGO_SECRET_KEY` | Signing key for sessions and CSRF tokens. Generated. |
| `POSTGRES_DB` | Database name |
| `POSTGRES_USER` | Database user |
| `POSTGRES_PASSWORD` | Database password. Generated. |
| `POSTGRES_HOST` | Database host |

## Django

| Variable | Default | Description |
|---|---|---|
| `DJANGO_DEBUG` | `False` | Never enable outside development. Debug pages expose settings, SQL and stack traces. |
| `DJANGO_ALLOWED_HOSTS` | `localhost,127.0.0.1` | Comma-separated hostnames this instance answers for |
| `DJANGO_LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` |
| `DJANGO_LANGUAGE_CODE` | `en-us` | Interface language |
| `DJANGO_TIME_ZONE` | `UTC` | Timestamps are stored in UTC regardless |

## Database

| Variable | Default | Description |
|---|---|---|
| `POSTGRES_PORT` | `5432` | |
| `POSTGRES_CONN_MAX_AGE` | `60` | Connection reuse, in seconds. `0` closes after every request. |

PostgreSQL is the only supported engine — see
[ADR 0002](adr/0002-postgresql-primary-database.md).

## Redis and Celery

| Variable | Default | Description |
|---|---|---|
| `REDIS_HOST` | `ansible-redis` | |
| `REDIS_PORT` | `6379` | |
| `CELERY_TASK_TIME_LIMIT` | `1800` | Hard kill, in seconds |
| `CELERY_TASK_SOFT_TIME_LIMIT` | `1500` | Raises an exception the task can catch |

Redis uses three logical databases: `0` broker, `1` results, `2` Django cache.

## Transport security

Secure cookies default to **on** whenever `DJANGO_DEBUG` is false. Override only
if you know why.

| Variable | Default | Description |
|---|---|---|
| `DJANGO_SECURE_COOKIES` | `not DEBUG` | `Secure` flag on session and CSRF cookies |
| `DJANGO_SECURE_SSL_REDIRECT` | `False` | Redirect HTTP to HTTPS. Enable only when TLS is actually terminated in front. |
| `DJANGO_SECURE_HSTS_SECONDS` | `31536000` (`0` when `DEBUG`) | HSTS max-age |
| `DJANGO_BEHIND_PROXY` | `False` | Trust `X-Forwarded-Proto` and `X-Forwarded-Host`. **Only enable behind a proxy you control** — otherwise a client can spoof these headers. |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | *(empty)* | Comma-separated origins, including scheme |

Always on, not configurable: `SECURE_CONTENT_TYPE_NOSNIFF`,
`SECURE_REFERRER_POLICY=same-origin`, `X_FRAME_OPTIONS=DENY`,
`SESSION_COOKIE_HTTPONLY`.

## Sessions

| Variable | Default | Description |
|---|---|---|
| `SESSION_COOKIE_AGE` | `28800` | Eight hours, in seconds |

Sessions also expire when the browser closes.

## API

| Variable | Default | Description |
|---|---|---|
| `CORS_ALLOWED_ORIGINS` | *(empty — denies all)* | Add the web UI origin when Module 2 lands |
| `THROTTLE_ANON` | `60/min` | Anonymous rate limit |
| `THROTTLE_USER` | `1000/hour` | Authenticated rate limit |

DRF requires authentication by default. An endpoint that should be public must
opt out explicitly — the health endpoint does.

## Initial administrator

Used only on first bootstrap. Changing these later has no effect; the account
already exists.

| Variable | Default |
|---|---|
| `INITIAL_ADMIN_USERNAME` | `admin` |
| `INITIAL_ADMIN_EMAIL` | `admin@localhost` |
| `INITIAL_ADMIN_PASSWORD` | Generated |

## Networking

| Variable | Default | Description |
|---|---|---|
| `ANSIBLE_API_PORT` | `47420` | Host port for the API |
| `POSTGRES_DEV_PORT` | `47432` | Loopback port, `docker-compose.dev.yml` only |
| `REDIS_DEV_PORT` | `47379` | Loopback port, `docker-compose.dev.yml` only |

## Reserved

| Variable | Status |
|---|---|
| `PLATFORM_ENCRYPTION_KEY` | Generated now, **not yet used**. Reserved for credential encryption in Module 3. |
| `PROJECT_NAME`, `PROJECT_ENV` | Metadata |

`PLATFORM_ENCRYPTION_KEY` is generated at bootstrap so that credential storage
can be added later without every existing installation needing a manual step.

## Where secrets belong

| Kind | Where | Example |
|---|---|---|
| Infrastructure secrets | `.env` only | `DJANGO_SECRET_KEY`, `POSTGRES_PASSWORD` |
| Operational settings | Database (`PlatformSetting`) | Retention policy, notification preferences |

Infrastructure secrets are never written to the database. Operational settings
may be flagged `is_secret`, which masks them in listings and in the admin — see
[security.md](security.md).

## Deployment checklist

Before exposing this to anything other than your laptop:

- [ ] `DJANGO_DEBUG=False`
- [ ] `DJANGO_ALLOWED_HOSTS` set to your real hostnames
- [ ] TLS terminated in front, with `DJANGO_BEHIND_PROXY=True`
- [ ] `DJANGO_CSRF_TRUSTED_ORIGINS` set
- [ ] Admin password changed from the generated one
- [ ] `.env` permissions are `600`
- [ ] Database backups scheduled and **restore tested**
- [ ] PostgreSQL and Redis still unpublished

Note that this project is alpha. This checklist makes a deployment less
dangerous; it does not make it production ready.
